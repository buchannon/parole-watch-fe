# Deploy: Parole Watch UI

**Manual only — the agent must never run these steps.**

The server has no Node runtime; the UI is a static build served from the
`parole-watch.jshowers.com` subdomain's own docroot on the Namecheap shared host.

## ⚠️ CRITICAL — do NOT touch `public_html`

`public_html/` is the **WordPress blog** (`https://jshowers.com/`) — never upload the
front-end there and never modify it.

**Key finding:** the real docroot for `parole-watch.jshowers.com` is **not**
`public_html/`. The subdomain is hosted in its own folder, `/parole-watch.jshowers.com/`
on the FTP server (account home `/home/jshomoek/parole-watch.jshowers.com/` via SSH
`ssh parole-watch-server`). **That** is where the front-end goes.

## Layout on the server

The subdomain docroot contains BOTH the deployed Django repo AND (now) the front-end
build:

```
/home/jshomoek/parole-watch.jshowers.com/
  index.html            ← front-end build (upload here)
  assets/               ← front-end build (upload here)
  favicon.svg           ← front-end build (upload here)
  .htaccess             ← docroot rewrite (see step 3)
  api/
    .htaccess           ← CloudLinux Passenger config: PassengerBaseURI "/api",
                          app root, env vars (generated by cPanel — do NOT edit)
  passenger_wsgi.py     ← Django entry (read-only)
  manage.py, parole_watch/, staticfiles/, ... ← Django repo (read-only)
```

The API is served by the CloudLinux Passenger app mounted at **`/api`** only
(`PassengerBaseURI "/api"` in `api/.htaccess`). Everything else under the docroot is
static, so the front-end at the root reaches the API at the same origin `/api/...`.

Pitfall: an earlier manual deploy accidentally uploaded the build **into the Django
package folder `parole_watch/`** (e.g. `parole_watch/index.html`,
`parole_watch/assets/`), which is why the site showed a directory listing of the Django
repo instead of the SPA. The build must live at the docroot **root**, never inside
`parole_watch/` or any subfolder.

## 1. Build locally

```bash
npm run build
```

Produces `dist/` (`index.html`, `assets/`, `favicon.svg`).

## 2. Upload to Namecheap

- Via FTP or cPanel File Manager, upload the **contents of `dist/`** (not the `dist/`
  folder itself) into the docroot root `/parole-watch.jshowers.com/` (FTP) or
  `/home/jshomoek/parole-watch.jshowers.com/` (SSH) — **never** `public_html/`.
- Do **not** overwrite the Django/Passenger files already there (`passenger_wsgi.py`,
  `api/.htaccess`, `manage.py`, `parole_watch/`, existing `.htaccess` rewrite rules).

## 3. SPA history routing: docroot `.htaccess`

Create or merge the following into the docroot `.htaccess` (at the same level as
`index.html`), preserving any existing rewrite/Passenger rules:

```apache
<IfModule mod_rewrite.c>
    Options -Indexes
    RewriteEngine On

    # Never rewrite existing files or directories
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteCond %{REQUEST_FILENAME} !-d

    # Let missing favicon files 404 so browsers fall back to <link rel=icon> (/favicon.svg)
    RewriteCond %{REQUEST_URI} !^/favicon\.(ico|svg|png|gif|webp)$ [NC]

    # Rewrite every non-/api request to index.html for SPA history routing
    RewriteRule !^api index.html [L]
</IfModule>
```

Do **not** remove the favicon `RewriteCond`. Without it, `/favicon.ico` (which has no real file)
gets rewritten to `index.html` and returns `200 text/html`; Chrome's default-favicon probe then
fails to decode it and shows a generic globe icon instead of `/favicon.svg` (works in a cached
tab, breaks on cold/incognito loads).

Why this works:

- `/api/*` paths do **not** match `!^api`, so they keep routing to the Passenger/Django
  app untouched (API endpoints + auth cookies).
- Every other non-file request (e.g. `/offenders`, `/login`, `/offenders/<id>`) is
  rewritten to `index.html`, letting react-router's BrowserRouter (history API) take over.
- `index.html` must sit at the docroot **root** so the relative `index.html` target
  resolves.
- `Options -Indexes` disables the LiteSpeed directory listing that appears when there is
  no `index.html` at the root.

## 4. Verify

- `https://parole-watch.jshowers.com/` loads the SPA (not a directory listing).
- Hard-refresh a deep route like `/offenders` and `/offenders/<id>` — SPA history
  routing falls back to `index.html`.
- `https://parole-watch.jshowers.com/api/auth/me/` still returns the Django API response
  (401 when logged out) — proves `/api` routing is untouched.
- `https://parole-watch.jshowers.com/assets/<hash>.js` and `/favicon.svg` return 200.
- Log in and confirm offender list/detail/settings render.

## Known limitations / security

The Django repo sits inside the web-accessible docroot, so files like `manage.py`,
`Dockerfile`, `stderr.log`, `.envrc`, and `parole_watch/urls.py` are still fetchable by
direct URL even though `Options -Indexes` hides directory listings. True separation means
relocating the Django app outside the docroot (e.g. `~/parole-watch-api`) and pointing
`PassengerAppRoot` in `api/.htaccess` at it — not yet done.
