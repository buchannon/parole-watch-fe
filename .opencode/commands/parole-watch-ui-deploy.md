# Deploy: Parole Watch UI

**Primary method: GitHub Actions (`.github/workflows/deploy.yml`).** The manual steps
below are fallback only — never run them as a routine deploy.

The server has no Node runtime; the UI is a static build served from the `parole.watch`
docroot on the Namecheap shared host.

## 0. Deploy via GitHub Action (primary)

`.github/workflows/deploy.yml` deploys automatically on every push to `main` (and via
manual `workflow_dispatch` run). It:

1. Checks out the code, `npm ci`, `npm run build`.
2. Copies the committed root `.htaccess` into `dist/` (the SPA rewrite is versioned in
   the repo now, so deploys are reproducible).
3. Runs `rsync --delete` of `dist/` → `/home/jshomoek/parole.watch/` over SSH
   (`jshomoek@jshowers.com:21098`), with `--exclude='api/' --exclude='cgi-bin/'
   --exclude='.well-known/'`.

The three excludes mean the Passenger mount point (`api/`), cPanel scaffolding, and SSL
validation files are **never** touched or deleted, while `--delete` safely clears stale
hashed assets in `assets/`.

### GitHub secrets required (already set: 2026-08-20)

| Secret            | Value         |
| ----------------- | ------------- |
| `DEPLOY_SSH_KEY`  | ed25519 deploy private key (public half in `~/.ssh/authorized_keys` on the server) |
| `DEPLOY_SSH_HOST` | `jshowers.com` |
| `DEPLOY_SSH_PORT` | `21098`        |
| `DEPLOY_SSH_USER` | `jshomoek`     |

If the workflow's rsync step fails with a permission/host-key error, the SSH host key
changed or the deploy key was rotated — re-run `ssh-keygen` + append the new public key
to `~/.ssh/authorized_keys` (via `ssh parole-watch-server`) and update `DEPLOY_SSH_KEY`.

## ⚠️ CRITICAL — do NOT touch `public_html`

`public_html/` is the **WordPress blog** (`https://jshowers.com/`) — never upload the
front-end there and never modify it.

**Key finding:** the real docroot for `parole.watch` is **not** `public_html/`. The
domain is hosted in its own folder, `/parole.watch/` on the FTP server (account home
`/home/jshomoek/parole.watch/` via SSH `ssh parole-watch-server`). **That** is where the
front-end goes.

## Layout on the server

The Django app lives **outside** the docroot at `/home/jshomoek/parole.watch.api`
(referenced by `PassengerAppRoot` in the `api/.htaccess`). The docroot contains only the
front-end build plus the web-server mount config:

```
/home/jshomoek/parole.watch/
  index.html            ← front-end build (upload here)
  assets/               ← front-end build (upload here)
  favicon.svg           ← front-end build (upload here)
  .htaccess             ← docroot rewrite (see step 3)
  api/
    .htaccess           ← CloudLinux Passenger config: PassengerBaseURI "/api",
                          PassengerAppRoot "/home/jshomoek/parole.watch.api"
                          (generated by cPanel — do NOT edit or delete)
                        ⚠️ api/ is the Passenger MOUNT POINT — an empty dir holding
                          ONLY this .htaccess, not a copy of the API. Not part of the
                          front-end build; never delete/rename/overwrite it.
  cgi-bin/              ← cPanel scaffolding (do NOT touch)
  .well-known/          ← SSL cert validation files (do NOT touch)
```

The API is served by the CloudLinux Passenger app mounted at **`/api`** only
(`PassengerBaseURI "/api"` in `api/.htaccess`). The Django code is at
`/home/jshomoek/parole.watch.api`, **not** under the docroot — so `manage.py`,
`parole_watch/`, etc. are never web-accessible. Everything else under the docroot is
static, so the front-end at the root reaches the API at the same origin `/api/...`.

## Fallback: manual build + upload

Only if GitHub Actions is unavailable. Follow the same rules as the workflow — never
touch `api/`, `cgi-bin/`, or `.well-known/`.

### 1. Build locally

```bash
npm run build
```

Produces `dist/` (`index.html`, `assets/`, `favicon.svg`).

### 2. Upload to Namecheap

- Via FTP or cPanel File Manager, upload the **contents of `dist/`** (not the `dist/`
  folder itself) into the docroot root `/parole.watch/` (FTP) or
  `/home/jshomoek/parole.watch/` (SSH) — **never** `public_html/`.
- Do **not** overwrite the server-side files already there (`api/.htaccess`,
  `cgi-bin/`, `.well-known/`).
- **Never `rsync --delete` against the docroot** — that would wipe `api/` (the Passenger
  mount point), `cgi-bin/`, and `.well-known/`. Sync the contents of `dist/` additively,
  or exclude those three paths explicitly (as the workflow does).

### 3. SPA history routing: docroot `.htaccess`

Create or merge the following into the docroot `.htaccess` (at the same level as
`index.html`), preserving any existing rewrite/Passenger rules:

```apache
<IfModule mod_rewrite.c>
    Options -Indexes
    RewriteEngine On

    # Never rewrite existing files or directories
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteCond %{REQUEST_FILENAME} !-d

    # Let missing favicon files 404 so browsers fall back to <link rel=icon> (/favicon.svg)
    RewriteCond %{REQUEST_URI} !^/favicon\.(ico|svg|png|gif|webp)$ [NC]

    # Rewrite every non-/api request to index.html for SPA history routing
    RewriteRule !^api index.html [L]
</IfModule>
```

Do **not** remove the favicon `RewriteCond`. Without it, `/favicon.ico` (which has no real file)
gets rewritten to `index.html` and returns `200 text/html`; Chrome's default-favicon probe then
fails to decode it and shows a generic globe icon instead of `/favicon.svg` (works in a cached
tab, breaks on cold/incognito loads).

Why this works:

- `/api/*` paths do **not** match `!^api`, so they keep routing to the Passenger/Django
  app untouched (API endpoints + auth cookies).
- Every other non-file request (e.g. `/offenders`, `/login`, `/offenders/<id>`) is
  rewritten to `index.html`, letting react-router's BrowserRouter (history API) take over.
- `index.html` must sit at the docroot **root** so the relative `index.html` target
  resolves.
- `Options -Indexes` disables the LiteSpeed directory listing that appears when there is
  no `index.html` at the root.

## 4. Verify

- `https://parole.watch/` loads the SPA (not a directory listing).
- Hard-refresh a deep route like `/offenders` and `/offenders/<id>` — SPA history
  routing falls back to `index.html`.
- `https://parole.watch/api/auth/me/` still returns the Django API response
  (401 when logged out) — proves `/api` routing is untouched.
- `https://parole.watch/assets/<hash>.js` and `/favicon.svg` return 200.
- Log in and confirm offender list/detail/settings render.

After a GitHub Action run, confirm the deployed `assets/` hashes match the new build
(the workflow's rsync output lists them).

## 5. Deploy notes

- The docroot `.htaccess` did **not** exist before the first deploy to the new
  `parole.watch` domain — it was created fresh with the exact SPA rewrite block above.
  There were no pre-existing rewrite rules to merge.
- The `api/` Passenger mount folder had been left as **`api_OLD/`** after the domain
  migration, which made `/api/*` 404 (LiteSpeed "Not Found") instead of reaching Django.
  Fix: `mv /home/jshomoek/parole.watch/api_OLD /home/jshomoek/parole.watch/api`
  (rename only — the `.htaccess` inside was untouched, and the Django repo at
  `/home/jshomoek/parole.watch.api` was not modified). If `/api/auth/me/` 404s on a
  future deploy, check that `api/` (not `api_OLD/`) exists in the docroot.
